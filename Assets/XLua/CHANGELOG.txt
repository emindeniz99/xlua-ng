Historical upstream changelog (English translation). Entries below describe the original releases and are retained for historical reference.

v2.1.15 — June 24, 2020
New features
1. Added a generated-code filter.
2. Improved the performance of matching delegates to bridges during reflection lookup.
3. Fixed an issue that prevented injection into mobile builds for Unity 2019.2 and later.

Changes

Bug fixes
1. Made reflection lookup for same-named delegate bridges consistent when generated code is disabled.
2. Fixed generated-code errors for nested structs marked with PackAsTable.
3. Added stack-space checks to reflection wrapper code.
4. Fixed a Unity Android crash caused by enum definitions with thousands of values, which produced a very large function with many branches.
5. Fixed a mismatch between the chunk name and script file name.
6. Fixed generated-code errors for enums in minimum-generation mode.
7. Fixed reflection-based enum registration when multiple enum members have the same value (for example, A and B are both 1); Lua could not access B.
8. Fixed `sbyte[]` being pushed to Lua as a string under .NET 4.
9. Fixed generated-code failures caused by generics.
10. Fixed handling of `out` parameters when injecting assemblies other than Assembly-CSharp.
11. Fixed cases where `xlua.private_accessible` could fail for nested classes.
12. Fixed an offset calculation error that could occur because Cecil did not update offsets automatically after inserting instructions.

v2.1.14 — February 27, 2019
New features
1. Added Nintendo Switch support.
2. Added Unity 2018 compatibility.
3. Added Android ARM64 support.
4. Added Visual Studio 2017 support for native-library builds.
5. Added the “XLua/Generate Minimize Code” menu item.
6. Prevented projects with invalid DLLs from interrupting code generation.
7. Added a more efficient `lua_pushstring` implementation, enabled with `NATIVE_LUA_PUSHSTRING`.

Changes
1. Changed the default compiler for the Windows library to Visual Studio 2017.

Bug fixes
1. Fixed a crash when an enum had `GCOptimize` but not `LuaCallCSharp`.
2. Added filtering for Editor classes to the sample configuration.
3. Fixed UWP compatibility.
4. Implemented same-signature methods introduced by interface inheritance.
5. Fixed inconsistent extension-method behavior when generated code is disabled.
6. Fixed nullable parameters causing all other parameters to become nil when the last argument was nil.

v2.1.13 — December 5, 2018
New features
1. Added the AdaptByDelegate injection mode.
2. Added `xlua.get_generic_method` for calling generic methods.
3. Added generic syntax such as `CS.System.Collections.Generic.List(CS.System.Int32)`.
4. Added injection options to ignore compiler-generated code and to omit base-call proxies.
5. Added ready-to-use automatic configuration examples for Lua scripting and hotfixes.
6. Added GC64 support for LuaJIT.
7. Added compatible bytecode support (one bytecode format for 32-bit and 64-bit systems).
8. Added a built-in Lua memory leak detection tool.
9. Added dynamic delegate-bridge instantiation: Lua functions can be called without `CSharpCallLua` configuration when the delegate has at most four parameters, all parameters are reference types, and the return type is void or a reference type.
10. Added `util.print_func_ref_by_csharp` to show Lua functions currently referenced by C#.
11. Added a mode of operation without the `CS` global variable.

Changes
1. Upgraded the VMs from Lua 5.3.4 to Lua 5.3.5 and LuaJIT 2.1b2 to LuaJIT 2.1b3.
2. Reduced delegate bridge code size.
3. Changed code-generation checks to use the PostProcessBuild event.
4. Adapted to Xcode 10; macOS builds no longer support 32-bit.
5. Static-member access now reports misspelled namespaces or class names.
6. Prevented deletion of the `CS` global table from disrupting xLua.
7. On Windows, if CMake fails with Visual Studio 2015 arguments, the library build now retries with Visual Studio 2017.
8. When generated code is disabled in the Editor, Blacklist is now checked as it is at runtime.

Bug fixes
1. Fixed generated code for arrays of generic types.
2. Fixed `TypeExtensions` marked with `LuaCallCSharp` causing checks such as `IsValueType` in Lua to always return true.
3. Filtered functions and fields containing pointers out of generated code.
4. Supported indexer properties whose name is not `Item`.
5. Fixed code generation and injection stopping when attribute initialization throws an exception.
6. Fixed generated code for empty enums in minimize mode.
7. Split initialization functions into smaller functions to avoid Unity Android crashes when executing large functions.
8. Fixed `Assignable` handling when `obj` is null.
9. Fixed generated-code errors when a nested class is not obsolete but its outer class is obsolete.
10. Fixed missing exception details when Lua logic threw an error with inline injection.
11. Fixed same-named public methods becoming inaccessible after `xlua.private_accessible` was used.
12. Removed the `out` keyword from parameters marked `[Out]`.
13. Fixed reflection lookup sometimes returning a function that was not an adapter.
14. Added missing `get_Item` and `set_Item` to exported code in minimize mode.
15. Fixed `xlua.private_accessible` not being applied automatically in IntKey mode.

Bug fixes
1. Added underscores to generated-code local variables to prevent symbol conflicts.
2. Omitted base-call proxies when a class was not included in the Hotfix list.
3. Refactored code for readability.
4. Fixed generated-code compilation failures involving `params byte[]`.
5. Fixed `xlua.private_accessible` failing for classes with private events.
6. For constructor injection, placed injected logic between a branch and a following `Ret` instruction.
7. Changed short branches to long branches when injected instructions exceed the short-branch range.
8. Fixed `CS.namespace.classname` being empty when a delegate was not a nested type of a class.
9. Prevented name conflicts with the Editor `Util` class.
10. Filtered out generic overrides that were causing errors.
11. Fixed generated-code compilation errors for empty enums.
12. Fixed UWP IL2CPP builds being unable to access any classes.
13. Fixed generated-code compilation and injection failures when hotfixing a method with a `params` parameter of a private type.
14. Made `GetHashCode` return the same value when two `LuaBase` instances refer to the same Lua object.
15. Fixed generated-code compilation failures for parameters marked `[Out]`.
16. Fixed generated-code errors for jagged arrays combined with multidimensional arrays.

7. Avoided generating code when a parameter was a generic type such as `ICollection`.

v2.1.9 — August 10, 2017

5. Added extension-method support under reflection.

Engineering improvements

Bug fixes

v2.1.0 — August 8, 2016
New features
1. Added no-GC passing of eligible structs to Lua. To qualify, a struct may contain nested structs but it and all nested structs may contain only these primitive types: `byte`, `sbyte`, `short`, `ushort`, `int`, `uint`, `long`, `ulong`, `float`, and `double`. 2. Reimplemented reflection to work more easily with generated code:
   a. Added extension-method support and `Enum.__CastFrom`.

   c. Aligned type mapping and variadic calls with generated code.

3. Simplified the code-generation menu and added a “Generate Minimum” option.

Bug fixes

Upgrade guide
Because some files changed, replacing the old library in place causes errors. Instead:
1. Delete the old XLua directory.
2. Extract `xlua_v2.0.2.zip` under `Assets`.
3. Run code generation again.
